The HTML is not the context

You already have the HTML bytes that went back. You do not yet know which file wrote them, or which Python objects the view handed that file.

Where this fits Roadmap: Phase 1, P1.8 — capture template render + context for non-DRF views. P1.6 stored the HTML string. P1.7 copied typed objects on the way in. Today you copy typed objects on the way out, before they become markup. See where this sits on the map →

The problem

You already know the HTML in the response. You do not yet know the live row that {{ item.product }} read. Real request: GET /menuitem/經典原味鍋/ — the HTML page, view menuitem_detail, url_name menuitem_page.

Missing · P1.8

The context dict

item still holds a live menuitem instance.

item → menuitem instance

The view menuitem_detail calls render(request, "includes/menuitem-detail.html", {…}). Django’s docs call that file a Type: a Template returned by get_template(). Django’s docs: “django.template.backends.django.Template is a thin wrapper adapting django.template.Template to the common template API.” The view asked for includes/menuitem-detail.html. That string lives on the inner compiled template as .name. Templates — Django backend , the dict a Type: a dict of names to Python objects — render(..., context). Django’s shortcut docs: “A dictionary of values to add to the template context.” The common render API: “If context is provided, it must be a dict.” On menuitem_detail the keys are item, meats, slug, ingredients, table_number. render() · Template.render , and combining them Type: a method — Template.render(context=None, request=None). Django’s docs: “Renders this template with a given context.” The shortcut render(request, name, context) is equivalent to get_template(name) then t.render(context, request) then wrap the string in an HttpResponse. Template.render · render() equivalent .

Render writes HTML. It does not convert the dict. After is_valid, product in validated_data is a new typed value. After Template.render, context["item"] is still a menuitem instance. The HTML is the return value — already in response.content. Copy the dict the view passed, while render runs. After get_response that dict is a local that went out of scope.

Same wrap as is_valid

The view writes return render(request, "includes/menuitem-detail.html", {…}). Do not replace django.shortcuts.render. The view already imported that name; changing the module later does not change the view’s copy. Wrap the method looked up at call time, same as Serializer.is_valid: django.template.backends.django.Template.render — the class get_template() returns.

Django has a Meaning: a signal Django fires in tests when a template is rendered. Django’s docs: “This signal is not emitted during normal operation of a Django server – it is only available during testing.” Same class of trap as connection.queries only populating when DEBUG is True. template_rendered signal. It does not fire on runserver. Do not listen for it. Replace the method.

Reuse encode

item is a model instance — encode already handles that. meats and ingredients are querysets, not lists. Encode will not walk them; the type name will be QuerySet. That is not a bug. The template’s {% for meat in meats %} is what walks the collection.

Keys the view did not put in the dict will be missing. user and csrf_token are added later, inside render, from context processors. Copying the dict the view passed will not show them.

Shape of the code

Put the wrap in the same try / finally as is_valid. Restore both. This is a copyable shape; wiring it into middleware.py is yours.

from django.template.backends.django import Template
# The class get_template returns. Not django.template.Template.

renders = []
original_render = Template.render

def probed_render(self, *args, **kwargs):
    # Run the real render. Skip this and the page never becomes HTML.
    result = original_render(self, *args, **kwargs)
    # The view called t.render(context, request). args[0] is that dict.
    context = args[0] if args else kwargs.get("context")
    renders.append({
        # Inner compiled template. The filename the view asked for.
        "template": self.template.name,
        # The dict the view passed, not csrf_token / user.
        "context": encode(dict(context) if context else {}),
    })
    return result

Template.render = probed_render
try:
    with connection.execute_wrapper(capture_sql):
        response = self.get_response(request)
finally:
    Serializer.is_valid = original_is_valid
    # Always restore. Same reason as is_valid.
    Template.render = original_render

captured["templates"] = renders
