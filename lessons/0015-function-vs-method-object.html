function object vs method object

You already know x.f() passes the instance as self. You do not yet know the two types Python names for MyClass.f and x.f.

Where this fits Lesson 0014 used both words. Python’s tutorial draws the line on one class. The wrap stores the class name (Template.render), not t.render. See where this sits on the map →

The problem

Same def f(self). Two lookups. Python gives them different types.

Already have · 0012

The two spellings of one call

x.f() is exactly equivalent to MyClass.f(x).

self is x either way

Missing · 0015

What each lookup is

The class name is a function object. The instance name is a method object.

MyClass.f · x.f

Docs example: 

class MyClass:
    def f(self):
        return 'hello world'

x = MyClass()
x.f()
MyClass.f(x)

“x.f is not the same thing as MyClass.f — it is a Type: a method object — the instance plus the function, packed together. “If the name denotes a valid class attribute that is a function object, references to both the instance object and the function object are packed into a method object.” Call: “a new argument list is constructed from the instance object and the argument list.” Method objects , not a Type: a user-defined function — what def f put on the class. “All attributes of a class that are function objects define corresponding methods of its instances.” MyClass.f is that function. You already saw one as fib in lesson 0014. Instance objects · Defining Functions .”

The wrap stores the class function. original_render = Template.render is MyClass.f. Then original_render(self, *args, **kwargs) can pass self in — same as original_is_valid(self, *args, **kwargs). t.render is x.f: already packed with one template instance. Do not store that.
