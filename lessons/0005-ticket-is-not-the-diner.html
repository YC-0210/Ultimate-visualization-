What request actually is

It is not a black box. Django wraps one visit in one Python object and passes that same object to middleware and to the view. Django’s docs call it an Type: an instance of django.http.HttpRequest. Django’s docs: “When a page is requested, Django creates an HttpRequest object that contains metadata about the request. Then Django loads the appropriate view, passing the HttpRequest as the first argument.” HttpRequest . Named pockets. Some arrive with the diner. Some get stamped later.

Same visit you already dumped after login: GET /api/menuitem/經典原味鍋/ with a sessionid ticket. Press each moment.

COOKIES is the parsed dict. The Cookie header is the raw string. Same ticket, two types. Django’s docs: “A dictionary containing all cookies. Keys and values are strings.” sessionid is one key in that dict. The session dictionary on the server is a different pocket — not inside COOKIES.

Also on the object, not drawn above: GET (query string), POST (form fields), META (every header), FILES. You do not need them for P1.3. Full list: HttpRequest. Pocket card: http-request.html.

Who loads the session

Your middleware is first in the restaurant app’s MIDDLEWARE list. On the way in, after your P1.1 print:

Django’s docs say AuthenticationMiddleware “adds the user attribute,” and it must run after SessionMiddleware. The type of that attribute is a Type: User if signed in, otherwise an AnonymousUser. Django’s docs: “If the current user has not logged in, this attribute will be set to an instance of AnonymousUser, otherwise it will be an instance of User.” Tell them apart with is_authenticated. AuthenticationMiddleware actually assigns a SimpleLazyObject that loads that instance on first access (reading is_authenticated is that access). The docs name the unwrapped result. Authentication in web requests · HttpRequest.user — never None just because nobody signed in.

Primary source: Authentication in web requests — “Django uses sessions and middleware to hook the authentication system into request objects.” The stored dictionary: request.session, a dict-like object from SessionMiddleware (How to use sessions).

Same peel as the view

json.dumps(request.user) fails for the same reason json.dumps(match.func) did: it is a live object, not strings and dicts. Pull three JSON-safe pieces. Keys only on the session — this app stores a table number in there, and login stores an id plus a hash. P1.3 is which keys exist, not the values. 

user = getattr(request, "user", None)
if user is not None:
    captured["is_authenticated"] = user.is_authenticated
    captured["username"] = user.get_username()
session = getattr(request, "session", None)
if session is not None:
    captured["session_keys"] = list(session.keys())
Put this next to the four route fields, not inside if match is not None. A 404 still went through SessionMiddleware and AuthenticationMiddleware. Field card: request-user.html. Copy the shape; wiring it into middleware.py is still yours.
