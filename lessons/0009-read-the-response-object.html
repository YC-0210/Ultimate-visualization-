Two objects after get_response

Django’s docs: Django builds an Type: an instance of django.http.HttpRequest. You already dump this object. Django creates it automatically for each visit. HttpRequest automatically. The view is responsible for returning an Type: an instance of django.http.HttpResponse (or a subclass). Django’s docs: “In contrast to HttpRequest objects, which are created automatically by Django, HttpResponse objects are your responsibility. Each view you write is responsible for instantiating, populating, and returning an HttpResponse.” HttpResponse . get_response(request) is that return value, after inner middleware on the way out.

A 404 still has a response. Missing route means no resolver_match. It does not mean no HttpResponse. Do not nest these four fields inside if match.

Four fields

Same as P1.2: do not dump the whole object. json.dumps(response) fails. Copy four JSON-safe pieces.

Type: a case-insensitive dict-like object — HttpResponse.headers. Django’s docs: “an interface to all HTTP headers on the response, except a Set-Cookie header.” Cookies on the response live on response.cookies. HttpResponse.headers does not include Set-Cookie. That header is on response.cookies — you already know cookies from lesson 0004. P1.6 dumps dict(response.headers). Leave cookies for later if they are missing from that dict.

Nest the four fields under captured["response"]. You already used headers and body for the request. Do not overwrite them.

Shape of the code

You already have response = self.get_response(request) inside the with. Read the four fields after that block — same place you already read request.user. This is a copyable shape; wiring it into middleware.py is yours. 

# Decode the body the same way you already decode request.body.
# content is bytes. decode turns those bytes into text.
try:
    response_body = response.content.decode("utf-8")
except UnicodeDecodeError:
    # Not text (an image, etc.). Record the byte length instead of crashing.
    response_body = f"<binary {len(response.content)} bytes>"

# A nested dict so these names do not overwrite request headers/body.
captured["response"] = {
    # The HTTP status. An int, JSON-safe as a number.
    "status": response.status_code,
    # Response headers. dict() makes it JSON-safe.
    "headers": dict(response.headers),
    # The body, now a string (or the binary placeholder above).
    "body": response_body,
    # Byte length of content. Count the bytes, not the decoded string.
    "size": len(response.content),
}

If response.streaming is True, there is no .content — Django’s docs say do not consume a streaming body in middleware. This restaurant GET is not that. Skip the body on a streaming response; still copy status and headers. StreamingHttpResponse
