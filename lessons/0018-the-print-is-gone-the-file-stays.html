One named file per request

Sortable, so “the most recent trace” is answerable.

20260901T094048502368-3f9a1c02.json

You know json.dumps already — write the object down as text. The variant that takes a file is Type: a function taking the object and a file — json.dump(obj, fp). Python's docs: “Serialize obj as a JSON formatted stream to fp (a .write()-supporting file-like object).” The tutorial: dump() “simply serializes the object to a text file.” Same keyword arguments as dumps — including ensure_ascii and default. json.dump · Saving structured data with json . No s: no string comes back, the bytes go to the file instead.

The filename has a job

P2.5 is “load and render the most recent trace.” If the name cannot be sorted, finding the newest means opening every file and comparing a field inside it. So put the clock in the name, most-significant first, and no : — that character is trouble in macOS filenames.

strftime("%Y%m%dT%H%M%S%f") gives 20260901T094048502368 — sorts lexically, which for this format is the same as sorting by time. Two requests in the same microsecond are still possible, so append part of the trace_id.

trace_id, for now

The schema's first field. Generate it server-side with uuid.uuid4().hex. In P4.3 the browser generates it instead and sends it as a header, and this middleware reads that value rather than making one — which is what lets the client and server halves join. Today nothing sends one, so you mint it.

Where sql goes

Your five queries are not five query_data stages. Three are the view's reads (menuitem, meattype, hotpotingredients); two are the django_session and auth_user rows, fetched because something touched request.session and request.user.

Do not invent attribution you did not capture. execute_wrapper is handed the SQL, not the caller. Nothing in Phase 1 records which stage caused a query, so keep sql as one top-level list in fire order — exactly as the schema in the roadmap has it. Splitting SQL per stage needs the probe to know the current stage, which is the context propagation D6 bought and P1.9 does not wire in.

Same, with a comment on each line

import uuid
# Makes the trace_id. uuid4 needs no input and does not repeat.
from datetime import datetime, timezone
# One clock read gives both started_at and the filename.
from pathlib import Path
# Path joins with / and can mkdir and open. No string concatenation.
from django.conf import settings
# BASE_DIR is the target project's root — the restaurant folder.

TRACE_DIR = Path(settings.BASE_DIR) / "supervisualizer-traces"
# Module level: computed once at import, not per request.

# top of __call__, before you capture anything
started = datetime.now(timezone.utc)
# timezone.utc so two machines' files sort against each other.

# end of __call__, replacing the print
trace_id = uuid.uuid4().hex
# .hex is the 32-character string. Without it you get a UUID object,
# which json cannot write — same trap as match.func.
trace = {
    "trace_id": trace_id,
    # Phase 1 mints it. P4.3 reads it from a request header instead.
    "framework": "django",
    # Which adapter produced this. The panel branches on nothing else.
    "started_at": started.isoformat(),
    # A string, because JSON has no date type.
    "endpoint": {
        "method": captured["method"],
        "path": captured["path"],
        "route_pattern": captured.get("route"),
        # .get, not [ ]: a 404 may have no resolver_match.
        "handler": captured.get("view"),
    },
    "stages": stages,
    # Your list from lesson 0016. Omit a kind whose probe list is empty.
    "sql": captured["sql"],
    # One flat list in fire order. Two of these five are session/auth.
    "notes": [],
    # Stays empty all through Phase 1. The LLM writes here in Phase 5.
}

TRACE_DIR.mkdir(parents=True, exist_ok=True)
# exist_ok: the second request must not crash on an existing folder.
name = started.strftime("%Y%m%dT%H%M%S%f") + "-" + trace_id[:8] + ".json"
# Clock first so lexical sort is time sort. No ":" — macOS dislikes it.
with (TRACE_DIR / name).open("w", encoding="utf-8") as f:
    # "w" truncates, but the name is unique so there is nothing to lose.
    # encoding="utf-8": Python's docs require it for JSON files.
    json.dump(trace, f, ensure_ascii=False, indent=2, default=str)
    # dump, not dumps: no string returned, it goes into f.
    # ensure_ascii=False keeps 經典原味鍋 readable. indent=2 for your eyes.
    # default=str is the same safety net your print already uses.
