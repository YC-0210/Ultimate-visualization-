HttpResponse pocket card

The object the view returns. Source: HttpResponse.

Django’s docs: Django creates the request automatically. “HttpResponse objects are your responsibility. Each view you write is responsible for instantiating, populating, and returning an HttpResponse.”

Where it appears in the probe

response = self.get_response(request)

After that line. A new object. The request parameter is still there — do not read status or body off it.

P1.6 pockets

PocketWhat it is
status_code An int. The HTTP status. 200, 404, …
headers Dict-like, case-insensitive. Dump with dict(response.headers). Does not include Set-Cookie — that is response.cookies.
content A bytes object. Same type as request.body. Decode for JSON/HTML.
size len(response.content) — byte count, not character count.

Not this

NameWhy not P1.6
request The request object. Method, path, user, session live here. Status and body do not.
json.dumps(response) Live object, same trap as match.func. Copy fields.
response.data DRF’s Python object before the JSON string. Later (serializer out). P1.6 is the wire body.
streaming .content If response.streaming is True, there is no .content. Do not consume streaming_content. StreamingHttpResponse.

JSON shape

"response": {
  "status": 200,
  "headers": { "Content-Type": "application/json" },
  "body": "{\"slug\": \"經典原味鍋\", …}",
  "size": 123
}

Nested under response so request headers / body stay put. A 404 still has this object — do not nest inside if match.
