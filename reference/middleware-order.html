Middleware order

The MIDDLEWARE list is wrapping, not a to-do list. Source: Middleware.

What one name is

A callable that takes a request and returns a response, like a view. Before it returns, it usually calls get_response(request) — the next middleware, or eventually the view.

Two walks of one list

PhaseOrder
Inward (before the view) Top of MIDDLEWARE first. Django’s docs: top-down.
Outward (after the view) Same list, backwards. Door waiter is first in and last out.

Django’s docs call this an onion: each class wraps the view. Middleware order and layering.

The dependency that bites

Order matters because one middleware can need a pocket another one sets. Django’s docs: AuthenticationMiddleware must run after SessionMiddleware (uses session storage). Middleware ordering.

Do not swap them in the live settings.py.
