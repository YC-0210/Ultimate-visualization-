validated_data

The dict is_valid leaves on the serializer. Source: DRF validation.

What it is

DRF’s docs: “When deserializing data, you always need to call is_valid() before attempting to access the validated data.” .is_valid() “Deserializes and validates incoming data.” .validated_data “Returns the validated incoming data.”

The type change on this project

KeyIn request.bodyIn validated_data
product str slug menuitem instance
meattype str slug meattype instance
hotpotingredients list of str list of hotpotingredients instances
quantity JSON number int
doublemeat JSON boolean bool
notes str str

The lookup is SlugRelatedField. Docs: queryset is “used for model instance lookups when validating the field input.”

Where P1.7 copies it

original = Serializer.is_valid
Serializer.is_valid = probed
try:
    response = self.get_response(request)
finally:
    Serializer.is_valid = original

Inside probed: call original, then if it returned True, encode(dict(self.validated_data)). Same timing as execute_wrapper: during get_response, not after. DRF has no execute_wrapper for serializers — you replace the method.

Not this

ThingWhy not P1.7
serializer_class P1.4. A class name on the view class. Not the live values.
request.body P1.1. Still JSON text. Types have not changed yet.
captured["response"]["body"] P1.6. JSON on the way out. Instances already became strings again.
GET /menuitem/經典原味鍋/ HTML page (menuitem_page). Does not call is_valid on input. Use POST /api/cart/item/.

JSON shape

"validated_data": [
  {
    "serializer": "restaurantAPI.serializers.cartitemSerializer",
    "data": {
      "type": "dict",
      "value": {
        "product": {"type": "menuitem instance", "value": "pk=…"},
        "quantity": {"type": "int", "value": 1}
      }
    }
  }
]

A list, like sql. Empty on GET /menuitem/經典原味鍋/. Do not invent the pk — copy yours.
