template + context

The template file and the dict of Python objects that render combines. Source: render(), Template.render.

What they are

Django’s shortcut: render() “Combines a given template with a given context dictionary and returns an HttpResponse object with that rendered text.” Common API: Template.render(context=None, request=None) “Renders this template with a given context.” “If context is provided, it must be a dict.”

django.template.backends.django.Template “is a thin wrapper adapting django.template.Template to the common template API.” That is the class get_template() returns. The filename lives on the inner compiled template: self.template.name.

The type on this project

KeyIn contextIn response.body
item menuitem instance HTML text inside {{ item.product }}
meats QuerySet <option> labels
slug str data-slug attribute text
ingredients QuerySet checkbox labels
table_number int or None the 桌號 line

Render writes HTML. It does not replace item in the dict. Contrast validated_data, where is_valid builds a new typed dict.

Where P1.8 copies it

original = Template.render
Template.render = probed
try:
    response = self.get_response(request)
finally:
    Template.render = original

Inside probed: call original, then encode(dict(context)) with self.template.name. Same timing as is_valid: during get_response, not after.

Not this

ThingWhy not P1.8
django.shortcuts.render The view already imported that name. Replacing the module later does not change the view’s copy.
template_rendered Test-only. “Not emitted during normal operation of a Django server.”
response.content P1.6. Already HTML. Types have already become markup.
user / csrf_token Context processors add these inside render. They are not in the dict the view passed.
POST /api/cart/item/ JSON. No Template.render. Use GET /menuitem/經典原味鍋/.
