OTel span anatomy

What the spec puts on a span, and which parts this repo borrowed. Source: Traces, Trace API.

Definitions, quoted

TermOTel's words
Trace “The path of a request through your application.” “A trace is made of one or more spans.”
span “A span represents a unit of work or operation. Spans are the building blocks of Traces.”
root span Has a trace_id “but has no parent_id. That's how you know it's the root span.”
context propagation “the core concept that enables Distributed Tracing.” The one thing D6 actually pays for.

The eight things on a span

statusUnset / Error / Ok. Default Unset means success.

The attribute rule

“Keys must be non-null string values. Values must be a non-null string, boolean, floating point value, integer, or an array of these values.”

No dicts. This is why P0.4a JSON-dumps the {type, value} encoding into one string attribute, and why a nested value is silently dropped with a warning rather than raising.
