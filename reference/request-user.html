Post-middleware state

What other middleware attached from a cookie. Not what the browser put in the URL. Source: Attributes set by middleware.

When it exists

Momentuser / session?
Your middleware, before get_response No — you sit first in MIDDLEWARE. Session and auth have not run.
Inside get_response, after SessionMiddleware then AuthenticationMiddleware Yes — attached on the way in.
The view Yes
Your middleware, after get_response Yes. Same place as the route fields.
404, no URL pattern matched Still yes. Unlike resolver_match, a miss does not skip these.

Docs: AuthenticationMiddleware (after SessionMiddleware), Authentication in web requests.

Fields P1.3 needs

WantReadNotes
auth user.is_authenticated A bool. False on AnonymousUser, True on a logged-in User. Do not use “user is None” — logged out is still an object.
who user.get_username() A string. Empty string when anonymous. Do not dump the user object.
session keys list(session.keys()) Names of slots only. This app writes table_number from ?table_number=. Login adds _auth_user_id, _auth_user_backend, _auth_user_hash. Do not dump values.

Peel, then dump

user = getattr(request, "user", None)
if user is not None:
    captured["is_authenticated"] = user.is_authenticated
    captured["username"] = user.get_username()
session = getattr(request, "session", None)
if session is not None:
    captured["session_keys"] = list(session.keys())

Sit this next to the route block, not inside if match is not None. json.dumps(request.user) fails the same way json.dumps(match.func) did.

request.user is assigned as a SimpleLazyObject that loads User or AnonymousUser on first access. Reading is_authenticated is that access. Docs still name the result as User or AnonymousUser: HttpRequest.user.
